# Filters
## FIR (used in coding)
$$y[n] = \sum_{k=0}^Mb_{k}x[n-k] = \sum_{k=0}^M h[k]x[n-k]$$
	(Difference equation of a filter is also written as the convolution of the impulse response and the signal)
$$H(\hat{w}) = \sum_{k=0}^Mb_{k}e^{-j\hat{w}k} = \sum_{k=0}^Mh[k]e^{-j\hat{w}k}$$

# Windows
**The filter length (samples) determines the cutoff frequency we can achieve**, therefore, *we can determine the impulse response with the cutoff frequency and the filter length* - COMPUTES THE COEFFICIENTS

It just cuts an ideal sinc to the samples provided, adding some extra touches to the end based on a window
$$h(n) = B·sinc(Bn) = B· \frac{\sin(\pi Bn)}{\pi Bn}, n\in \mathbb{Z}$$
- $B = 2f_{c}$: Normalized bandwitdth in Hz

Then we window is, usually avoiding rectangle windows
$$h_{w}(n) = w(n)·h(n), n\in \mathbb{Z}$$
# Downsampling
Downsampling a signal $x(n)$ by a factor $L$ is 
$$x_{d}(n) = x(nL)$$

# Upsampling
$$x_{u}(n) = \sum_{m=-\infty}^\infty x(m)\delta(n-mM) = \left\{  x\left( \frac{n}{M}, n=0, \pm M, \pm 2M, \dots; 0, else \right)  \right\}$$
Essentially, it just zero pads and then it *interpolates*

# Filter banks 
We will be dividing the frequency in banks
*An input signal $s(n)$* is processed at the encoder by a parallel bank of $(L-1)$-th order FIT bandpass filters $H_{k}(z)$. 
The bandpass analysis outputs
$$v_{k}(n) = h_{k}(n)*s(n) = \sum_{m=0}^{L-1}s(n-m)h_{k}(m)$$
Are decimated by a factor of M, resulting in subband sequences
$$y_{k} =  v_{k}(Mn) = \sum_{m=0}^{L1}s(nM-m)h_{k}(m)$$

*The sum of all these signals will be the original signals
```ad-warning
THIS IS NOT WINDOWING, THAT IS TIME DOMAIN
```

Particular bands might be more periodic than others, so band analysis is conveniently done through these banks.

![[3-Time-frequency-analysis-filter-banks-and-transforms.pdf#page=12&rect=183,127,746,456|3-Time-frequency-analysis-filter-banks-and-transforms, p.12]]
	Downsampling is done for optimization. Keeping the same size for all the band passed signals is opposite to compression.
	The range of frequencies chosen by each bandpass depends on the number of filters $M$
	*The first filter is a low pass and the last one is a high pass, with the ones in the middle being shifted band passes from low to high*

Dividing the signal into bandpassed signals does not apply any compression, **we will apply it later to $y_{m}(n)$**, that is, **on the individual bands**

# DCT (Discrete Cosine Transform)
Instead of multiplying a complex exponential, it multiplies by a **cosine**
- *It retains phase information, even if the output is just real valued*
- For this reason, DFT is often preferred 

```ad-info
The number of samples is still the same of both
```

## Cosine weights, phase and compression
**DFT:** Cosine and sine components give an explicit magnitude and phase
**DCT**: Fixed cosine patterns receive teal, signed weights
- WE CAN'T OBTAIN THE PHASE EVEN THOUGH IT'S THERE

SHifting a waveform changes its DCT weights - weighted cosines preserve its timing

DCT HELPS WITH *COMPRESSION*
- Correlated samples often give a few large coefficient and many small ones
- We can differentitate important coefficients and quantize them differently
- Quantization and coding reduce the bit rate - INVERTIBLE TRANSFORMATION

# MDCT (Modified Discrete Cosine Transform)
```ad-summary
title:TLDR
Best for compression (doesn't apply compression though), it stores less samples and then it uses antialiasing techniques
```


- We use 50% window overlap 
	- We store half the size of the window then - **critically sampled representation**
	
This means that instead of storing 2N samples, we use N real coefficients with an N sample hop.

*This creates a lot of aliasing due to inverse frames*, but some window and hop size settings can cancel these distortions. Implementations use DCT IV or FFT algorithms using a *sine window*
$$h_{k}(n) = h(n)\sqrt{ \frac{2}{N} }\cos\left[ \left( \frac{\pi}{2} \right) +\left( k+\frac{1}{2} \right)\left( n+\frac{N}{2}+\frac{1}{2} \right)\right]$$

```ad-example
See [[Spectrogram visualization of STFT and MDCT]]
```

Applied to **filter banks**, we of course want to have a good frequency resolution, that is, narrower lobes. This depends on the window, though the choice of window also depends on the frequency analysis we want to make. As in MDCT, we would use a sine window

![[3-Time-frequency-analysis-filter-banks-and-transforms.pdf#page=32&rect=46,49,895,458|3-Time-frequency-analysis-filter-banks-and-transforms, p.32]]

For long lasting sounds -> Prioritize frequency resolution

On both cases, **we want to avoid diffusion**. For instance, with a higher time resolution, castanets will become a single line in the grid, MAKING IT EASIER TO ENCODE
